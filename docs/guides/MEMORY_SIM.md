# 记忆网络规模仿真（20 万条消息）

脚本：`scripts/memory-sim.mjs`（离线、可复现、不写真实 brain、不发 QQ）
目的：在 20 万条模拟群聊消息下，压测记忆网络的形成 → 去重 → 矛盾降权 → 容量淘汰 → 衰减归档 → 每周巩固 → 召回 全链路，找出规模瓶颈。

## 1. 方法

- 语料：`--messages 200000 --days 60 --seed 42`，24 个主题、16 个发送者、私聊占 12%，约 3333 条/天。
- 消息类型：闲聊 42%、寒暄 14%、事实 14%、偏好 8%、决定 6%、承诺 4%、提问 5%、重提 5%、精确重复约 12%（压测写入去重）。
- 引擎：用 `src/memory/model.mjs` 的纯函数（`textSimilarity` / `detectContradiction` / `scoreMemory` / `computeStrength` / `materializeBrain` / `hebbianWeight`），内存内实现：
  - 写入：候选抽样（每实体最近 40 + 均匀 40）→ 长度比预筛 → 相似度 ≥ 0.82 合并；
  - 矛盾：决定类消息对同主题活跃记忆做 `detectContradiction`，候选 ≤2 且 score ≥0.4 时把旧的标记 superseded；
  - 容量：`active > maxMemories` 时按「强度×新近」淘汰最弱（永久/日记保护）；
  - 每天：`materializeBrain({archive:true})` 归档 faded/purgeDue；每周：short→long 提升 + 同实体近重复归档；
  - 召回：每 50 条消息发一次查询，top6 + 强化 + 共激活突触。
- 真实写盘对照：同一台机器用真实 `MemoryService.remember` 顺序写（每次全量 normalize+save），用作耗时校准。

## 3. 结论

1. **分层配额把 long 从容量淘汰里救了出来**：26,501 条容量淘汰全部发生在 short，long 淘汰 0 条；long 最终稳定在 1.83 万（低于 2 万配额），第 1 天出生的记忆存活率从 0% 回到 37.9%。
2. **short 仍被高淘汰压制**：short 配额 5,000、存活 4,993，说明短期待办/寒暄类事实依旧快速轮换，符合设计；代价是 mid 年龄的随机召回几乎没有（同主题近似记忆过多）。
3. **主题召回只有 25%**：按「这个主题最近一条」作为目标时，top6 里经常被更旧/更高强度的同主题记忆挤掉——说明同主题聚合（第 5 条建议）仍是必要改造，而不是再加权重。
4. **最近决策召回 98.9% 非常稳**：决定类记忆一旦写入，在 60 天窗口内几乎每次都能被带回，这是最值得当作主指标的信号。
5. **去重依旧砍掉约 24% 写入**；打开不设限后衰减才显得有用（12.6k 归档），但活跃 3.2 万仍偏多，且 brain.json 已 41 MB。
6. **查询延迟不是问题（P50 < 2ms），写盘才是**：真实 MemoryService 顺序写 300 条要 5.2s（17.3ms/条），20 万条乐观约 1 小时，且全量 normalize+save 随规模超线性——所以 v1.6 必须做增量 journal（已实现）。

## 5. 复现

```bash
# 分层配额（默认 long 20000 / short 5000）
node scripts/memory-sim.mjs --messages 200000 --days 60 --seed 42 \
  --json-out state/memory/sim-report-200k.json

# 对照：不设限，观察衰减路径
node scripts/memory-sim.mjs --messages 200000 --days 60 --seed 42 \
  --cap-long 200000 --cap-short 200000 \
  --json-out state/memory/sim-report-200k-nocap.json

# 真机写盘校准（会创建临时 repo，不触碰真实数据）
node scripts/memory-sim.mjs --messages 2000 --days 10 --real-probe 300
```

## 6. 说明

- 语料是合成数据，主题/模板重复度高于真实群聊，绝对数值仅作量级参考；趋势（容量瓶颈、衰减被掩盖、写盘超线性）与真实一致。
- 仿真不经过 `MemoryService` 的磁盘事务，只复用其纯函数；真实服务的行为差异主要是每次写入的 `normalize + save + appendEvent` 成本。
