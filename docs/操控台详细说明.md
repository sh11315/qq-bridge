## 1. 这是什么

一个本地 Web 控制台，把 QQ 机器人整套链路收在一页里管理：

| 组件 | 端口 | 作用 |
|---|---|---|
| **NapCat（Framework）** | 3000 HTTP / 3001 WS / 6099 WebUI | 注入 QQ 客户端，提供 OneBot 接口 |
| **桥接 bridge** | 3100 | QQ 消息 ↔ DSH 会话的翻译层：路由、工具、黑话、Token 记账、看门狗 |
| **DSH Web** | 3080 | Agent 运行时（模型、会话、工具、上下文压缩） |
| **WorkBuddy LAN** | 8321 | 本地 OpenAI 兼容网关（备用/基础模型） |
| **控制台 console** | 7788 | 你正在看的这个页面：状态、配置、日志、备份、测试 |

控制台本身不聊天，它负责**观测 + 控制**：看到什么在跑、改什么立即生效、出错时能定位和恢复。

## 2. 打开与安全

### 2.1 访问方式

- 浏览器打开 `http://127.0.0.1:7788`（只监听本机）
- 页面加载时会自动带上令牌；外部脚本调用需要请求头：

```
x-console-token: <state/console-token 文件内容>
```

### 2.2 令牌与权限

- 令牌文件：`state/console-token`（自动生成，长随机串）
- 拿到令牌 = 能控制机器人（改配置、发消息、重启服务），**不要外传、不要截图暴露**
- 白名单外的会话不会走 Agent；管理员（ownerQQ）才有本地工具权限
- 控制台所有写操作都会写日志，可在「实时日志」里追溯

### 2.3 桌面托盘启动器（桌面快捷方式「QQ Bridge 控制台」）

源码在 `desktop-app\launcher.cs`，编译产物 `desktop-app\QQBridgeConsole.exe`：

- **双击打开**：控制台没跑会自动拉起，然后打开控制台页面
- **打开方式是 Edge 独立窗口**（`--app` + 专用 profile `desktop-app\EdgeProfile`），不污染日常浏览器、不刷标签页；找不到 Edge 才退回默认浏览器
- **托盘菜单**：打开控制台 / 打开使用说明 / 全部启动 / 全部重启 / 全部停止 / 打开项目目录 / 开机自启 / 退出（控制台继续运行）/ 退出并停止全部服务
- **看门狗**：每 20 秒探活 `/api/health`，控制台进程意外退出会自动拉起并气泡提示
- 支持 `--autostart` 静默启动（只驻留托盘，不弹页面）

### 2.4 刷新规则

| 改动 | 生效方式 |
|---|---|
| `ui.html`（页面） | 浏览器 **F5** 即可 |
| `server.mjs`（控制台后端） | **重启控制台进程** |
| `src/bridge.js`（桥接） | **重启桥接**（总览卡片或顶栏「全部重启」） |
| DSH preset 提示词 | **重启 DSH**（模型页不会提示，改动后需手动重启） |
| config.json 里的多数配置 | 保存接口会热更新，无需重启 |

## 3. 顶栏与全局操作

| 按钮 | 作用 |
|---|---|
| **▶ 全部启动** | 按顺序启动 DSH → NapCat → 桥接（WorkBuddy 由自启动负责） |
| **↻ 全部重启** | 全部服务重启（会短暂断开 QQ，通常几十秒恢复） |
| **■ 全部停止** | 停止桥接/NapCat/DSH 等 |
| **⟳ 刷新状态** | 立即拉一次 `/api/status` |
| 服务卡片按钮 | 每个服务独立「启动 / 重启 / 停止」；NapCat 卡还有「打开 WebUI」 |
| **数据同步指示器** | 右上角绿点 +「已同步 · N 秒前」；超过 15 秒未更新变黄，提示数据可能过期。只读页面每 4 秒自动静默刷新，表单页不自动刷新（避免覆盖编辑） |
| 模型卡片按钮 | 「🎯 一键切换」跳到模型页 |

> 启动顺序是固定的：DSH 先就绪，NapCat 再注入，最后桥接连上。停止时反向。**先停桥接再停 NapCat** 可以减少报错噪音。

## 4. 页面详解（20 个页面）

### 4.1 总览（overview）

**服务与状态**（7 张卡：NapCat / 桥接 / DSH / WorkBuddy / 模型 / 额度 / QQ 账号）

每张卡显示：运行状态、端口、PID、内存、CPU、运行时长；NapCat 卡额外显示账号/昵称，WorkBuddy 卡显示版本与模型数，模型卡显示当前 provider/model/来源平台/节点。

**错误在卡片上的显示规则**：
- **当前故障**（服务未运行，或错误发生在本次进程启动之后）→ 红色两行告警，超长自动截断，悬停看全文
- **历史异常**（错误发生在进程启动之前、已自动重启恢复）→ 只留一行灰字：`⏱ 历史异常（12:39:29，已恢复）· 查看日志 →`，点击跳日志页
- 所以「以前崩过、现在已经好了」不会在卡片上顶着大红条误导你

**额度卡（按当前运行 provider 自动换口径）**

不再写死「API 余额」，而是先看当前实际在跑的模型（`dsh.chain` 生效项 → `dsh.provider`，`currentRunProvider()`），再决定显示什么：

| 当前 provider | 卡片标题 | 显示内容 |
|---|---|---|
| `xdpool` / `xdpool-global` | 池积分 / 额度 | 池内账号积分合计（`display: "2196 积分"`）、池账号数、冷却中数量；点「🔍 明细」列出每个池账号的积分与冷却状态 |
| `workbuddy` | 额度 · WorkBuddy | 「桌面账号额度」，口径为桌面端登录账号的额度，不计 API 费用（顺带对网关做 1.5s 探活） |
| `deepseek-account` | 订阅额度 | 「订阅额度」，DSH 账号制没有公开余额接口 |
| 其它（直连 API / 桌面 provider） | API 余额 | 沿用 `config.api` / `~/.dsh` 导入凭据去查 deepseek/moonshot 的余额接口 |

池积分是异步读的（插件 `status` 接口国际版首次可能要 20s+），读取期间卡片显示「读取中」并保留上一次成功值（标 `（池状态刷新中，显示上次结果）`），不会闪成「不可用」。

**当前配置**（只读摘要 + 快捷跳转）

- 模型：`provider/model`（可点「去改模型」）
- 模式：`reserved2`（QQ 仿真模式）
- 直连 API：未启用 / 已启用
- 直连触发：@（含引用自己 / 唤醒词） / 全部
- 白名单：群 N / 私聊 N / deny N
- 管理员：ownerQQ
- Token 花费：累计花费 · token 数 · 轮数 · 缓存命中率
- 最近日志：条数 / 错误数

**最近错误 / 告警**

按时间倒序列出 warn/error：来源服务、时间、内容，每条可点击跳日志。每条会判断是否已恢复：

- 错误时间早于该服务当前进程的启动时间 → 标注 **「已恢复（重启于 HH:mm:ss）」**（绿标、✓ 图标）
- 否则标注 **「当前」**（黄标、✖ 图标）

常见正常噪音：NapCat 重启期间的 `token 自愈失败`、`快速登录不可用`（已限频/降级）、DSH 冷启动瞬间的 sidebar 403（会自动重试）。

**快捷入口**

6 个服务入口（卡式）：桥接控制台（3100）、DSH Web（3080）、NapCat WebUI（6099）、WorkBuddy 网关 healthz（8321）、诊断备份、使用说明。

下方「⚡ 常用操作」一行按钮：全部重启 / 重启 NapCat / 强制进阶模型 / 恢复自动路由 / 强制基础模型 / 一键备份 / Token 花费 / state 目录 / 掉线历史。

**运行环境**

控制台地址/PID/内存、项目目录、Node 版本、桥接端口、config.json 校验结果、构建版本说明。

### 4.2 模型（model）

#### ① 模型配置

- **Provider**：下拉选择（隐藏 `vision-toolkit-*` 包装 provider）
- **模型**：该 provider 下的模型列表
- **思考强度（reasoningEffort）**：`off / low / high / max`（不支持的模型自动降级为 auto）
- **☑ 同时写入 DSH 的 agent-default-model**：影响 DSH Web GUI 新建会话默认模型
- **💾 保存并应用**：写入 `config.json` + 让桥接对下条消息生效（不重启服务）

#### ② 一键切换 · WorkBuddy LAN 模型

- 按厂商分组的模型卡片（28 个），搜索框过滤
- **思考强度**下拉：切换时一起应用
- **🧪 测试全部模型**：服务端并发实测每个模型是否可用（写入 `state/workbuddy-model-test.json`）
- **⟳ 重新拉取**：重读网关 `/v1/models`
- 标注「非聊天」的是图片/视频生成模型，不能用于 chat
- 点击模型卡 = 立即切换（会校验并回读配置）

#### ③ 模型分工（基础 / 进阶）★ 核心

| 行 | 说明 |
|---|---|
| **基础模型** | 纯文字回合使用；用顶部「模型配置」或一键切换来改 |
| **基础工具面** | WorkBuddy 基础模式下只保留 **15 项**（读消息/发消息/引用/已读/唤醒/等待/查详情与成员/共用小黑板等）；功能会话开启后再按域收窄（chat 面 23 项开关） |
| **进阶模型** | 下拉选任意 `provider/model` + 思考强度，点「保存进阶模型」热生效 |
| **进阶触发** | **私聊默认进阶**；群聊按每条消息独立判断：图片/视频/表情/合并转发，或命中关键词，或带 URL；不做保持窗口；会话忙且需换模型时自动中断旧回合重投；图片以媒体本体随唤醒投递 |

#### ⑦ XD Pool · 账号池与路由链 ★ 自动容错

把 XD Pool 插件的「账号池 / 门内模型 / 内置组合链」和**跨 provider 的故障切换链**放到控制台里，不用再去 DSH 设置页。

| 区块 | 说明 |
|---|---|
| **国内版（cn）/ 国际版（global）池** | 显示账号数、每个账号的积分与冷却状态、池内模型启用数（如 `18/18`）、目录来源与调度策略；「用这个池」= 直接切到该池的 `hy3`（没有则用第一个可用模型） |
| **🔄 重扫账号** | 调插件 `accounts/rescan`，把桌面端新登录的账号吸收进池 |
| **⟳ 拉取模型目录** | 调插件 `models/refresh`，重读两区域模型列表 |
| **🪜 路由链** | 1–8 条 `provider/model` 顺序；链首是主力，失败自动切下一条；「冷却」分钟数到点自动回链首；可勾选「自动切换」（关掉则只保留手动按钮） |
| **⏮ 切到链首 / ⏭ 切到下一条 / 💾 保存路由链** | 手动干预与持久化；保存写 `config.json` 的 `dsh.chain` |
| **组合链（插件内置）** | 每个 XD Pool 插件自带 fallback/round-robin 组合链（只在插件内部模型间切换，不能跨 provider），这里可以新增/删除/保存到 `~/.xdpool/aggregate.json` |

**自动切换怎么判定**：控制台每 8 秒增量扫一次 `state/bridge.log`，出现 `429 | 11128 | unapproved channel | 请求被拦截 | INVALID_REQUEST | rate limit | quota | 积分 | 额度 | 余额不足 | insufficient | upstream_connection_failed | upstream_timeout | connection failed | model_not_found | does not exist | unknown model | 调用失败 | 请求失败 | 超时 | timed out` 之一，且该行提到**当前生效条目**（链首或链中段都算，只要日志里出现当前 provider/model）→ 切下一条并热生效（写 `config.json` + 桥接 `/api/dsh/model` + DSH `agent-default-model`）。其中 `11128 / unapproved channel / 请求被拦截` 是腾讯 WorkBuddy 国内网关的**通道校验拒绝**（DSH 的系统提示/UA 命中其指纹），不是额度问题，重试无意义，必须切走。保护：60 秒防抖、10 分钟内最多 5 次，避免疯狂来回切；切换历史写在 `state/chain-runtime.json`，卡片上会显示「生效中」和最近切换记录。

> 为什么不用插件自带的组合链：插件组合链的成员必须来自同一个插件目录（池模型或聚合渠道），而「WorkBuddy 的 hy3 挂了换到 XD Pool 国际版的 hy3」是**跨 provider**，只能由控制台/桥接层实现。

预设链（2026-10-31 调整）：① `deepseek-account/deepseek-flash` ② `xdpool/hy3` ③ `xdpool-global/hy3` ④ `workbuddy/hy3`（通道受限，暂放末尾），冷却 15 分钟。原因：WorkBuddy 国内网关从 2026-10-31 22:31 起对 DSH 的请求返回 `11128 Illegal API invocation from an unapproved channel`，链首放它会每 15 分钟被判失败一次；修好通道或装回兼容补丁后，可以在「模型 → 路由链」里把 `workbuddy/hy3` 拖回链首再保存。路由链行尾的小徽标是**工具调用能力**（`工具✓` / `工具✗` / `工具?`），保存时若某条不支持工具调用会弹黄色提示（QQ 机器人切到它会「哑」，只能回空气）。

失败判定（2026-10-31 补）：`429`、`500/502/503/504`、`11128 / unapproved channel / 请求被拦截`、`DeepSeek Messages request failed`、`All chat models failed`、`APITimeoutError`、`rate_limit_error`、额度不足、超时等都会触发自动切链。桥接侧任何回合错误都不把原始报错贴到 QQ：完整错误只写 `state/bridge.log`，私聊最多两分钟收一句「刚才卡了一下，没接住」，群聊完全不吭声；模型故障恢复后按冷却时间自动回链首。

#### ⑨ 基础 / 进阶双上下文（互不共享）

每个 QQ 会话最多持有两套 DSH 会话：

- `sessions[key]`：当前激活的上下文
- `parkedSessions[key]`：另一边"停放"的上下文（`basic` / `advanced`）
- `sessionVariants[key]`：当前用的是哪一套

切换逻辑：本回合该用进阶 → 把基础上下文停放、恢复进阶上下文；反之亦然。日志会写 `会话 xxx 切换到进阶/基础上下文：session-…`。重置会话时两套一起清掉。

持久化在 `state/sessions.json`，重启桥接不丢。

#### ⑩ 五域会话分工（按功能拆会话）

同一个 QQ 会话（群/私聊）会按「这回合在干什么」落到**不同的 DSH 会话**，每个域有独立的上下文与模型档位；历史消息不共享，但**最近消息快照、记忆、黑话库每回合都重新注入**，所以换个会话也不会突然"失忆"。

| 域（variant） | 什么时候走它 | 模型档位 | 工具面 | 说明 |
|---|---|---|---|---|
| `chat` | 普通聊天 | 群聊 → 基础；私聊 → 进阶 | 基础 15 项 / 进阶全套（chat 面 23 项开关） | 最常用；群聊纯文字走基础省钱 |
| `sticker` | 消息/指令里出现「表情包、斗图、贴纸」（含消息媒体为 face/mface/emoji/sticker） | 基础 | 只放表情相关工具（发/列/看/收藏/备注/自画像） | 表情回合不需要推理，用基础模型省额度 |
| `vision` | 图片、视频、图片类文件、`[转发消息`、看图提问（「看图、这张图、图里、图片里、截图、照片」） | 进阶 | 全套（含看图） | 媒体本体以附件形式给模型；群聊媒体默认**不**升级到进阶模型 |
| `voice` | 「语音、读出来、念一下、发条语音、说句话」 | 进阶 | 全套（含 `qq_send_tts`） | TTS 回合独立，避免和文字上下文互相污染 |
| `web` | 「搜索、搜一下、搜一搜、联网、上网、查一下、查一查、最新、翻译、新闻」或带 URL | 进阶 | 全套（含联网搜索） | 需要新鲜信息时强制进阶 |

- 路由函数在桥接里是 `routeTurn(key, media, opts)`，返回 `{domain, level, variant}`；日志会写「本回合走 聊天模式·基础 / 表情 / 看图 / 语音 / 联网」。
- 优先级：`sticker` > `vision`（有媒体）> `voice` > `web` > `chat`，一条消息命中多个时按此顺序取。
- 持久化：`state/sessions.json` 里的 `sessions`（当前激活）、`parkedSessions`（另一档停放）、`sessionVariants`（当前用哪一档）；重启桥接不丢。
- 与 ⑨ 的关系：⑨ 管「基础/进阶两档上下文」，⑩ 管「按功能再切域」；两者叠加后，一个 QQ 会话最多同时存在多个域的 DSH 会话（例如聊天基础 + 看图的进阶）。
- 想减少会话数量（省上下文、少建会话）：把「其它会话轮换 token」调大、或只用一种模型档位；想让它更"记得住"：把轮换阈值调大即可。
- 排障：模型页「最近路由」能看到每回合的 domain/level/原因；「会话」页能看到当前各会话的 sessionId 与 Token。
### 4.3 实时日志（logs）

> **重启时看到的「端口被残留进程占用」「bridge 进程退出（code=1）」不是故障**：重启流程会先停旧进程再拉新进程，端口释放有几秒延迟，被结束的进程退出码也是 1。控制台现在会先等旧进程把端口放开再启动，主动停止的日志写成 `X 已停止（重启/停止请求）`（info）；只有**真正的外部残留进程**才会出现 warn。


- 数据源：SSE 实时推送 + `state/bridge.log` + 子进程输出
- **服务分栏**：全部 / console / bridge / napcat / dsh / workbuddy
- **⏸ 暂停**：冻结滚动（后台仍记录）
- **🗑 清屏**：只清控制台内存显示，不动 `bridge.log`
- **⤓ 导出 .log**：下载当前过滤结果
- **📋 复制**：复制当前显示
- **关键词搜索**：按服务名/内容过滤（如 `session`、`error`、群号）
- **级别**：all / info / warn / error / debug
- **最多显示**：300 ~ 3000 行
- **☑ 自动滚动**

### 4.8 直连 API（api）

绕过 DSH、直接用 OpenAI 兼容后端回复（默认关闭，`config.api`）：

- **开关**：启用/停用直连
- **Base URL / 模型 / API Key**（Key 只显示掩码，留空=不改；启用前必须先有 Key）

### 4.10 NapCat（napcat）

> **WorkBuddy LAN 卡死会自动接管**：如果之前控制台重启过、WorkBuddy 子进程成了“孤儿”，端口还在但健康检查已死，控制台会确认它是安装目录下的 `WorkBuddy-LAN.exe` 后结束它并重新拉起（不会误杀同名程序）。真正的其他程序占端口仍然只报错、不动它。
> 连续拉起失败 3 次后，自愈冷却会自动拉长到 4 倍并在日志里提示手动重启，避免每 90 秒刷三条错误。


- **📱 NapCat 登录**：状态、账号、QQ 版本、OneBot 版本、WS/HTTP 连接；「↻ 重启 NapCat」
- **🔳 扫码登录**：未登录时获取/刷新二维码（来自 6099 WebUI API）；已登录不需要
- **💻 系统信息**：版本、CPU、内存、磁盘、QQ 进程、网络连接数（WebUI 同款数据）
- **👥 最近登录账号**：快速登录列表（多账号时点选）
- **🕘 掉线历史**（持久化 `state/napcat-offline.json`，最近 100 条）
  - 统计：**今日异常 N 次**（含掉线/被踢/自动重启）、**累计离线 X 分钟**；下方一行「最近原因：… · 时间」
  - 表格：时间（今天只显示 HH:mm:ss，更早显示 MM-DD HH:mm:ss）/ 类型（掉线·被踢·自动重启·恢复）/ 原因
  - 原因会翻译成人话，例如「读不到 NapCat 登录态（进程可能重启中）」「账号掉登录（SelfOffline）→ 已自动重启重登」「恢复在线（离线 2 分钟）」

**🐳 Docker 模式（无头 QQ，推荐）**

**🧩 运行参数（WorkBuddy 优化）★ 核心**

> 「默认」列是**代码默认值**；本机 `config.json` 当前覆盖了这几项：群聊轮换 = `0`、其它会话轮换 = `0`（`0` 表示关闭“单轮 prompt 过大自动轮换”），「需要换模型时自动中断长回合」= **关**（`autoInterrupt:false`）。「单次等待上限」界面值 180 秒，但 reserved2/WorkBuddy 下仍被 `socialV2.wait.reserved2MaxMs=60000` 截到 **60 秒**生效。

| 参数 | 默认 | 作用 |

| 群聊会话轮换（token） | 45000 | 群聊单轮 prompt 超过就换新 DSH 会话（防上下文膨胀） |
| 其它会话轮换（token） | 80000 | 私聊等 |
| 快照压缩系数（0.1~1） | 0.4 | 唤醒消息快照的字符压缩比例 |

**🗣 主动机会（它自己冒泡）**（设置页，紧挨运行参数）

没人说话时让它自己找由头开口。判定链（纯函数 `src/core/proactive.mjs`）：
每 3~10 分钟随机到点判定一次 → 安静超过阈值（群 15 分钟 / 私聊 25 分钟）→ 机会概率（基础 30% / 55%，随安静时间缓慢爬升、最多 +35%）→ 由头加成（上次没聊完 +20%、pendingThought +10%、手上有具体的事 +35%）→ 时段与刷屏惩罚（01:00–08:00 **直接跳过**，`quietHardBlock=true`；关掉后改为 ×0.08。群里最近 1 小时自己发过 ≥5 条 ×0.35）→ 私聊冷却（两次主动至少隔 30 分钟）→ 每小时/每天硬上限 → 会话不忙才真正唤醒。

> 「默认」列是代码默认值。本机 `config.json` 当前为：判定间隔 **2~10 分钟**、群聊概率 **0**（群里不主动开口）、私聊概率 **0.6**、每小时上限 **群 2 / 私聊 4**、私聊冷却 **25 分钟**；其余（阈值、每日上限、静默时段、刷屏惩罚、由头多样性、回复热度）与默认一致。改完保存即时生效，以页面显示为准。

命中后按权重挑一个由头：followup（接上次没聊完的话题）/ thought（补一句没说完的话）/ mood（分享此刻心情）/ share（分享一件小事）/ poke（拍一拍或表情）/ idle（轻轻开口）。唤醒提示里会带上【这次主动的由头】和活人感边界：可以半截话、可以发两条、别每次用「在吗」开场、没话就安静收尾。

| 参数 | 默认 | 作用 |
|---|---|---|
| 启用主动机会 | 开 | 总开关；关掉后不再有主动回合 |
| 判定间隔（分钟，最小~最大） | 3~10 | 每次随机取区间内一个间隔再判定，避免机械准时 |
| 群聊静默多久算冷场（分钟） | 15 | 群聊冷得快，阈值更短 |
| 群聊每次基础概率 | 0.3 | 之上还有安静时长爬升与由头加成 |
| 私聊静默多久算冷场（分钟） | 25 | 一对一更允许安静 |
| 私聊每次基础概率 | 0.55 | 私聊更容易「想找你」，但受冷却与上限约束 |
| 每小时上限（群 / 私聊） | 2 / 3 | 超了直接跳过 |
| 每天上限（群 / 私聊） | 8 / 16 | 防止一天刷太多 |
| 私聊冷却 | 30 分钟 | 两次主动之间的最短间隔 |
| 静默时段 | 01:00–08:00 直接跳过 | `quietHardBlock=true` 时深夜完全不打扰；关掉后才是概率 ×0.08 |
| ▶ 立刻试一次 | — | 无视阈值直接投递一次主动机会（填 `group:群号` / `private:QQ号`），用于验证链路 |

补充：WorkBuddy 模式**也支持**主动机会（早期为省额度直接跳过，现改为默认放开，可用配置 `socialV2.proactive.skipWorkbuddy=true` 关回去）；所有字段都在 `config.json` 的 `socialV2.proactive`，保存时会保留不认识的字段。

**由头多样性**：记录最近 5 次主动用的由头，重复出现的按 `diversityPenalty` 降权（默认 0.35，连着两次同由头再减半）；命中后若和上次同一类，提示词会要求「换个方式，别重复同一套路」。

**按回复热度调整**：每次主动都记 pending，之后有人接 → `replied=true`、超过 `proactiveOutcomeWindowMs`（默认 2 小时）没人接 → `false`；最近 8 次结果的回复率就是热度。热度高时概率 ×1.4 且安静阈值 ×0.85（更爱找你），热度低时概率 ×0.6、阈值 ×1.25（更收敛）。

### 4.16 成长（growth）

侧边栏 **🌱 成长** 页，把「情绪 / 自升级提案 / 一个月测试台 / 他今天大概」四件事放在一起，原则一句话：**自评不算数，外部卡尺由主人判定**；日常采样则只给「大概」，不给细节。

- **此刻情绪**：下拉 8 种情绪（烦躁 / 低落 / 平静 / 开心 / 疲惫 / 紧张 / 兴奋 / 委屈）+ 强度滑杆 0–100% + 一句备注，点「设为此刻情绪」生效。情绪只影响语气、**默认 24 小时自动过期**，不改人设、不定死性格；主人随时可以覆盖。当前情绪卡显示情绪名、强度条和剩余时间，下面是最近 8 条情绪记录。
- **情绪来源**：`自动（时段 / 对话 / 记忆）` 表示由 v1.10 情绪动力学在唤醒时自动更新，旁边「为什么」显示本次变化原因（时段回落 / 命中哪类对话 / 记忆回声）；历史里带 ⚙ 的条目为自动写入。
- **待主人批准的自升级提案**：她只有建议权，批准权在主人。每条显示标题、细节目、最多 3 条证据、提案类型（客服腔 / 问句收尾 / 主动开口过多）与「自评嫌疑 xx%（只是自评，不算数）」；**外部卡尺只显示「待主人判定 0/1」**，由主人拍板，页面不给她自评的满分。点「✓ 批准」提案才进入语气注入，点「✗ 驳回」留档；已决定的提案在下方列出。
- **一个月测试台**：点「▶ 启动一个月测试」写 `state/memory/trial.json`（30 天，不碰记忆库、不改行为）。仪表显示开始时间、已运行 / 剩余天数、唤醒次数、有记忆注入的唤醒次数、**唤醒注入率**、**情绪复读次数**；**开封探针**看问「你在开封」能否从记忆里命中（找到则显示记忆 id / 强度 / 状态）；**漂移指标**看平均回复长度、客服腔率、问句收尾率。数字只是参考，外部卡尺（主人主观判定）优先。
- **他今天大概（日常采样）**：底部卡片，每 5 分钟记一次「前台程序 + 空闲时长」，由控制台的采样守护执行（控制台在跑才采，退出即暂停）；**不读窗口标题、不截图、不记键盘**，密码管理器只记为「私事」。页面显示今天采到多少条、机器人实际看到的那句话（`【他今天大概】09:00–11:40 写代码…`）、按活动类型的分钟数与前 14 段时间线。右上角「📷 采一次」立即采一条，「暂停采样」写 `state/life-log/disabled` 且不再产生新数据（可随时恢复；控制台重启后仍按这个开关）；日志保留 60 天。
- 接口：`GET/POST /api/memory/emotion`、`GET /api/memory/proposals`、`POST /api/memory/proposals/decide`、`GET /api/memory/trial`、`POST /api/memory/trial/init`、`GET /api/lifelog`、`POST /api/lifelog/toggle`、`POST /api/lifelog/sample`。后端方法缺失时页面显示「部分接口未就绪」，重启控制台后恢复；测试台报告由 `scripts/memory-trial.mjs --report --json` 生成。

### 4.17 主从委派（delegate）

主会话只接上下文、分派任务、把结果说成人话；联网检索 / 看图 / 表情这三类工具活交给短命子智能体。子智能体只拿任务卡、只回结构化 JSON，做完即归档。页面用于观测与配置，不直接改聊天内容。

**顶部配置条**：启用开关、每小时上限（默认 10）、超时 ms（默认 120000）、最多来源数（默认 4），改完点「保存配置」立即写回 `config.json` 并热更新，不用重启。

**指标 chips**：总派发 / 成功 / 失败 / 成功率 / P50 / P95 / 平均耗时。

**按链路**：看图、联网搜索等各自的派发次数、成功率、平均耗时。

**延迟**：只统计成功派发（失败多为媒体过期、超时或解析失败，单独列在失败数里）。

**刷新 / 清空记录**：右上角「⟳ 刷新」重新拉统计；「清空记录」只清空 `state/delegate-runs.jsonl` 里的观测日志（不影响配置、记忆和真实聊天），用于把测试数据清掉后重新开始计。

**最近的委派**：最近 50 条记录（时间/类型/结果/耗时/来源数/内容或错误），失败会显示具体原因（例如「图片获取失败，无法查看图片内容」——QQ 老消息的媒体 URL 会过期）。

**注意**：只有 bot 主动唤醒时产生的委派才会入账；网页会话/普通会话里调用会被会话工具面拒绝。

## 5. 核心机制（看配置前先理解这些）

### 5.1 基础 / 进阶模型分工

- **基础模型**：WorkBuddy 网关模型（默认 `workbuddy/deepseek-v4.1-flash`），便宜但慢（约 1.2–1.7s/次）
- **进阶模型**：DeepSeek 官方（默认 `deepseek-account/deepseek-flash`，high），快（约 0.6s）且支持视觉
- **自动路由（auto）**：每条消息独立判断
  - 消息带图片/视频/表情/合并转发 → 进阶
  - 文本命中关键词（图片/搜索/查一下/代码/文件/翻译/记忆/黑话/梗/语音…可自定义） → 进阶
  - 带 URL → 进阶
  - 其它纯文字 → 基础
- **强制模式**：模型页「强制基础 / 强制进阶」一键覆盖
- **中断长回合**：会话正忙且新消息需要换模型 → 中断旧回合并按新模型重投（防"旧回合吞掉新消息"）
- **断连回退**：基础模型连接失败 → 自动切进阶、强制进阶 3 分钟、2 秒后重投一次
- **工具面（按会话门控）**：WorkBuddy 基础回合只保留 **15 项**基础工具（含共用小黑板 `board`；功能会话开启后按域收窄，chat 面 23 项开关）；进阶回合临时放开全套工具，**窗口按会话 key 记账**（只有该会话能用，基础回合会清掉自己的窗口）。基础上下文调进阶工具会 403「工具未启用」；私聊进阶回合内实测可用（sticker-list 200）
- **上下文隔离**：基础 / 进阶各有一套 DSH 会话，切换时"停放/恢复"，两边历史互不污染
- **群聊 anyMessage（可选）**：开启后每条群消息都会唤醒；提示词会追加"醒≠必回，只在被 @/被直接问到/话题相关时发言"，其余直接收尾潜水

### 5.2 上下文压缩

三层叠加：

1. **唤醒快照**：WorkBuddy 下按系数压缩字符/未读/最近条数（群聊再压一档）
2. **会话轮换**：单轮 prompt 达到阈值（群聊 45k / 其它 80k）自动换新 DSH 会话
3. **DSH compaction**：DSH 自带的历史压缩（日志会显示"上下文已压缩 N 条"）

代价：换会话/压缩后会更早"失忆"。可用运行参数回调到 60–80k 或调大快照。

### 5.3 沉睡观察与等待

- 收尾/潜水前的强制观察窗：默认 **15 秒**（运行参数可调）
- `qq_wait_for_messages` 单次上限：WorkBuddy 下 **60 秒**
- 看到「标记已读失败：还需等待约 X 分钟」= 未完成观察窗的正常提示，不是故障

### 5.4 黑话学习

- 群消息滚动进入学习窗口，定期提取候选 → 联网考究 → 入库
- **旧梗规则**：群友玩旧梗/引用旧话题时也要提取候选
- **补课线索**：机器人自己说"看不懂/接不上"→ 记录最近消息为线索并立刻重新提取
- 数据：`state/slang.json`（候选/已确认），可在黑话页（DSH 工作区）查看

### 5.5 自愈与看门狗

| 场景 | 机制 |
|---|---|
| NapCat 卡死（端口在但 HTTP 死） | 连续探测失败/内存超限 → 自动杀 QQ 重新注入 |
| 被踢下线 | 记录 kickInfo；10 分钟内 ≥2 次暂停自动重启，避免踢号循环 |
| WorkBuddy 网关假活 | 自愈改用 `/healthz` 判断，失败自动重启 |
| 桥接 token 失效 | 自动重新发现 WS token；失败日志 5 分钟限频一次，恢复时提示 |
| 模型连接错误 | 自动切进阶模型重试 |
| DSH 冷启动慢 | 启动等待 120s（重 profile 实测 55~60s）；超时日志提示看 `state/dsh-child.log` |
| DSH 配置写坏起不来 | `dsh-child.log` 会报 `failed to parse overlay ... cordis.patch.yml: bad indentation`，按行号修好 YAML 后点「启动」即可；控制台本身不猜配置内容 |
| Docker 引擎没起来（NapCat 拉不起来） | 先看 `com.docker.service` 是否停止、WSL `docker-desktop` 是否 Stopped；控制台会先尝试 `sc start com.docker.service` 再启动 Docker Desktop，等引擎真正返回 ServerVersion 才 `compose up`；权限不够时日志会提示用管理员模式。正常安装后该服务已设为自动启动 |
| 服务恢复后旧告警还在 | 探活为 up 时自动清掉该服务的「最近错误/告警」；自愈恢复也会清零失败计数，不再持续报冷却 |
| QQ 账号掉线（端口都在但发不出消息） | 每轮用 `get_login_info` 判断账号是否真在线；离线超过 90 秒自动调 NapCat WebUI 快速登录，失败每 5 分钟重试并提示去「查看登录」扫码 |
| 回合里长时间等待 | `qq_wait_for_messages` 单次最多 60 秒（`socialV2.wait.reserved2MaxMs`），长观察拆成多轮；避免一个回合挂 5 分钟、新唤醒在 DSH 队列里堆三四条 |

**管理员模式（可选）**

控制台、桥接、DSH 默认以当前用户权限运行。确实需要管理员权限时：

1. 右键 `scripts\enable-admin-mode.ps1` →「以管理员身份运行」，UAC 点「是」；
2. 脚本注册登录任务 `QQBridge-ConsoleAdmin`（最高权限）并立刻切换，然后重启桥接与 DSH，让它们继承管理员令牌；
3. 验证：控制台「实时日志」出现「控制台以管理员权限运行」，`/api/status` 的 `console.admin` 为 `true`。

撤销：右键 `scripts\disable-admin-mode.ps1` →「以管理员身份运行」。

> 注意：提权后模型链路（桥接/DSH）也在管理员令牌下运行，请只在你信任白名单与 preset 时使用。

### 5.6 会话、工具与能力矩阵怎么联动

一条消息进来会依次回答四个问题：

1. **该不该醒**（唤醒条件：@ / 名字 / 关键词 / 提问 / 拍一拍 / 概率 / 指定成员；群聊可开"任何消息都唤醒"）
2. **走哪个域**（⑩ 五域：chat / sticker / vision / voice / web）
3. **用哪档模型**（基础 = 群聊纯文字；进阶 = 私聊/媒体/关键词/强制；WorkBuddy 挂了自动回退进阶）
4. **给多少工具**（基础 15 项，含小黑板；进阶回合按会话临时放开全套，15 分钟窗口）

能力矩阵（4.2-⑧）是把第 3、4 步和**真实模型能力**对齐的工具：某模型 `tools=false` 时，它接不住「发消息」这类工具，切过去机器人就会"哑"——所以：

- 路由链保存时会逐条校验，命中有问题的条目会弹告警；
- 模型配置选到 `tools=false` 的模型会弹黄条；
- 群聊基础模型优先选 `tools=true` 的（推荐 `hy3` / `fast-model` / `glm-5.3-flash`）。

### 5.7 主动机会（它自己冒泡）

没有新消息时，桥接按 `config.json` 的 `socialV2.proactive` 给 AI 制造"主动开口"的机会（判定逻辑是纯函数，见 `src/core/proactive.mjs`）：

```
每 3~10 分钟（默认，每次在区间内随机取一个间隔）判定一次
  └─ 会话安静够久？（群 15 分钟 / 私聊 25 分钟；按回复热度可 ×0.85 / ×1.25）
       └─ 基础概率（群 0.3 / 私聊 0.55）+ 安静爬升（min(0.35, 超出阈值倍数 × 0.12)）+ 由头加成
            └─ × 热度系数（0.6~1.4）→ 静默/刷屏惩罚 → 冷却与每小时/每天上限
                 └─ 投递 proactiveCheck 唤醒 → AI 看最近记录 → 有由头才发 1~2 条
```

- 由头加成：上次没聊完 +0.2、`pendingThoughts` +0.1、手上有具体的事（cue）+0.35；最近 5 次用过的由头重复出现会降权（`diversityPenalty=0.35`，连着两次同由头再减半）
- 时段保护：01:00–08:00 **直接跳过**（`quietHardBlock=true`，避免夜里把当天额度耗光）；关掉 hard block 后才是概率 ×0.08
- 群聊保护：最近 1 小时自己已发 ≥5 条 → 概率 ×0.35
- 私聊保护：两次主动至少隔 30 分钟（`privateCooldownMs`）；上限 每小时 3 / 每天 16；群聊为 每小时 2 / 每天 8
- 回复热度：最近 8 次主动的回复率，高时概率 ×1.4 且安静阈值 ×0.85，低时 ×0.6 且 ×1.25
- 本机当前值（`config.json`）：判定间隔 **2~10 分钟**、群聊概率 **0**、私聊概率 **0.6**、每小时上限 群 2 / 私聊 4、私聊冷却 **25 分钟**；其余与默认一致
- 不想被打扰：设置页「🗣 主动机会」关掉总开关，或把对应概率调成 0
- 想立刻验证：点「▶ 立刻试一次」，填 `private:QQ号` / `group:群号`，会无视阈值直接投递一次
- 改完立即生效（写 `config.json` + 热推桥接），不用重启；所有字段都在 `config.json` 的 `socialV2.proactive`，保存时保留不认识的字段

### 5.9 共用小黑板（跨功能会话的短期事实板）★ 治「两路各说各的」

**为什么有这块板**：一个 QQ 会话被拆成 chat / sticker / vision / voice / web 五套 DSH 上下文（见 4.2-⑩），各路的「刚看到什么」互相不可见 —— 实测出现过「看图那边早知道外面下雪，聊天这边还在问冷不冷」。长期事实有记忆（`qq_memory_*`），最近几条有消息快照，中间这段**短期、跨会话**的事实由小黑板补。

| 项目 | 说明 |
|---|---|
| 存哪 | `state/board.json`（`{"version":1,"boards":{"private:100000001":[{"at":…,"by":"vision","text":"…"}]}}`） |
| 生效范围 | 同一个 QQ 会话的五个功能会话共享；不同 QQ 会话互不可见 |
| TTL | 默认 6 小时（`socialV2.board.ttlHours`），过期自动消失 |
| 上限 | 每块板最多 24 条（`maxEntries`），超出丢最旧 |
| 注入 | 每回合唤醒提示词注入最近 8 条（`promptEntries`），空板时给「可以用 `qq_board_write` 记一条」的引导 |
| 写入口 | ① AI 自己调 `qq_board_write`；② 控制台会话详情手动「写入」 |
| 读出口 | AI 在提示词里直接看到；也可 `qq_board_read` 主动读 |
| 清理 | `qq_board_forget`（单条/清空）；会话「重置」会顺带清空该板 |
| 关掉 | `config.json` → `socialV2.board.enabled=false`（提示词不再注入，工具也按 `tools.board` 关） |

**AI 该往黑板写什么**：天气/温度、约定（几点见、去哪）、对方状态（在忙/在搬东西）、正在做的事、已查到的结论（汇率、比分、新闻要点）。**不该写**：长期人设与偏好（进记忆）、流水账与寒暄、超过 80 字的段落。

**排障**：
- 提示词里没有「【共用小黑板·本会话】」→ 看 `socialV2.board.enabled` 是否为 false、`GET http://127.0.0.1:3100/api/socialV2/prompt?key=…` 的 `board.enabled`（这是**桥接 3100** 的接口，控制台 7788 不代理，调用要带桥接令牌）
- 写了但另一路没反应 → 确认两个功能会话是同一个 QQ 会话 key；黑板是 per-key 的
- 写入报 403 → 工具门控：该功能会话没开 `board` 工具（基础会话也带，除非 `socialV2.tools.board=false`）

## 7. 常见问题

**Q：控制台页面白屏/401？**
A：确认 `state/console-token` 存在且页面从 `127.0.0.1:7788` 打开；重启控制台会重新读取令牌。

**Q：改了提示词（preset）为什么没变？**
A：preset 在 DSH 启动时加载，需重启 DSH；运行参数里的「沉睡前观察」会自动同步 preset 文件，但同样要 DSH 重启后提示词才完全一致（桥接闸门已即时生效）。

**Q：重启控制台后 QQ 掉线？**
A：控制台负责 NapCat 进程，重启时可能连带 QQ 子进程；通常自动快速登录，几十秒恢复。频繁掉线看「最近错误/告警」与 NapCat 页。

**Q：群聊被重置后它不记得之前聊过什么？**
A：正常。重置=换新 DSH 会话；旧消息可通过黑话库/记忆逐步补回，或以后用更温和的"轮换阈值调大"。

**Q：为什么 Token 页基础模型花费是 ¥0？**
A：WorkBuddy 走订阅额度，价格表已置 0；不是统计漏了。

**Q：日志里「token 自愈失败」「快速登录不可用」要紧吗？**
A：多为 NapCat 重启窗口的瞬时提示，已限频/降级；恢复后会自动出现 `token 自愈恢复`。

**Q：总览出现过「致命异常」红条，但服务现在正常？**
A：那是历史记录（错误发生在进程重启之前）。卡片现在只显示当前故障；历史异常降级成一行灰字，详情在「最近错误/告警」里并标注「已恢复（重启于 …）」。

**Q：机器人说「工具未启用」/ 调表情包返回 403？**
A：说明这个会话当前是**基础上下文**（群聊纯文字），进阶工具被门控拦了。发图/命中关键词让它走进阶回合，或私聊它（私聊默认进阶），即可在 15 分钟窗口内使用全套工具。

**Q：群里每条消息都醒，会不会太吵？**
A：设置 → 运行参数可取消「群聊任何消息都唤醒」；开着时提示词会要求"醒≠必回"，只在与它相关时开口。

**Q：让它发语音，它说没有语音功能？**
A：语音功能之前默认关闭（`socialV2.voice.enabled=false`）。现在已启用并支持 TTS：设置页「🔊 语音」可开关/限频/发测试语音；对话里说「发一条语音」「念一下…」即可。若仍说没有，检查该开关与 `tools.sendVoice`。

**Q：它从来不会主动找我/主动在群里说话？**
A：以前 WorkBuddy 模式在代码里直接跳过了「主动机会」，所以只会被动回。现已放开：设置页「🗣 主动机会」可开关、调私聊/群聊静默阈值与概率；私聊 1 小时最多主动一次，深夜概率 ×0.3。想立刻验证点「▶ 立刻试一次」。
**Q：为什么它说"两路各说各的"（明明刚说过天气又问一遍）？**
A：功能会话把同一 QQ 会话拆成五套上下文，彼此看不到对方刚看到的东西。现在有**共用小黑板**（见 5.9）：看图/联网查到的事实会写进板子，聊天那路回答前先扫一眼。手动补一条：会话 → 「详情」→ 小黑板「写入」；想清掉：单条「删」或「清空」。排查 `GET http://127.0.0.1:3100/api/socialV2/prompt?key=...`（桥接侧）里的 `board.text` 是否为空。

**Q：小黑板里的东西会一直留着吗？**
A：默认 6 小时过期、每块板最多 24 条；长期事实请让它写进「记忆大脑」（`qq_memory_append`），别塞黑板。

**Q：XD Pool 卡片显示「读不到池状态：首次读取中」？**
A：正常。池状态是异步拉取的（国际版目录 10~20 秒），服务刚重启或第一次打开时先显示这次，几秒后自动刷新；也可点「⟳ 」强制刷新。

**Q：额度卡显示「读取中」或「不可用」？**
A：额度卡按**当前运行的 provider** 换口径：池 → 池积分、WorkBuddy → 桌面额度、DeepSeek 账号 → 订阅额度、直连 → API 余额。读池积分较慢时会先显示「读取中」并保留上次结果；切链/切模型后短暂 pending 属正常。

**Q：路由链会自己乱切吗？**
A：有保护：只有**当前生效条目**（链首或已切到的链中段）失败才切下一条，不是任意报错都切；60 秒防抖、10 分钟内最多 5 次；命中「冷却」分钟数后自动回链首。切了什么、为什么切，都记在卡片「最近切换」和 `state/chain-runtime.json`。

**Q：NapCat 掉线后为什么必须扫码？**
A：扫码只在"被踢下线/登录态失效"时出现。容器模式已配置 `ACCOUNT` 快速登录，普通重启会自动用已存登录态；若被踢（桌面 QQ 同账号登录、异地登录），必须扫码一次。**桌面 QQ 与容器不能同时登同一账号。**

**Q：Docker 容器起不来？**
A：先确认 Docker Desktop 在跑（`docker info` 有 ServerVersion）。控制台启动 NapCat 时会自动尝试拉起 Docker Desktop；仍失败就看「实时日志」里的 docker 报错，或手动 `docker compose up -d`（目录 `napcat\docker`）。
**Q：桌面快捷方式打开的不是浏览器页面？**
A：新版启动器用 Edge 独立窗口（`--app` + 专用 profile），像桌面应用；托盘里还有「打开使用说明」和看门狗（控制台挂了自动拉起）。

## 9. 一图流：一次群聊消息的完整链路

```
群友 @ 机器人
  └─ NapCat（OneBot WS:3001）→ 桥接 3100
       ├─ 白名单 / 模式检查 → 不在白名单就丢弃
       ├─ 黑话窗口记录消息（供学习）
       ├─ 唤醒判定（@ / 名字 / 关键词 / 提问 / 拍一拍 / 概率 / 指定人）
       ├─ 会话忙？ → 若需换模型就中断旧回合（可按参数关闭）
       ├─ 路由①：判断域 chat / sticker / vision / voice / web
       ├─ 路由②：定档位 基础 / 进阶（群纯文字→基础；媒体/关键词/私聊→进阶）
       ├─ 取会话：ensureSession(key, "域:档位")（停放另一档，互不污染）
       ├─ 组装提示词：最近消息快照 + 记忆 + 黑话 + 身份补充 + 主动/群聊说明
       │    └─ DSH 3080（session.prompt）→ 模型（WorkBuddy 8321 / DeepSeek / XD Pool）
       ├─ 模型调工具（qq_send_message 等）→ 桥接校验工具面 → NapCat → QQ
       ├─ 回合结束：Token 记账（按模型/域/会话）→ 控制台 Token 页
       └─ 收尾：沉睡观察 15s → mark_read / set_wake_config
```

### 9.1 没人说话时（主动机会）

```
每 3~10 分钟（默认，随机）判定一次
  └─ 该会话安静够久？（群聊 15min / 私聊 25min，按热度可 ×0.85 / ×1.25）
       └─ 掷骰命中概率？（群聊 0.3 / 私聊 0.55 + 安静爬升 + 由头加成；本机当前群 0 / 私聊 0.6）
            └─ 时段与上限（01:00–08:00 直接跳过；每小时 群 2 / 私聊 3；每天 群 8 / 私聊 16）
                 └─ 投递 proactiveCheck 唤醒（与真人消息同一条链路）
                      ├─ AI 看最近聊天记录，自己找由头发 1~2 条
                      └─ 没话/不合适 → mark_read 收尾继续潜水（不硬发）
```

### 9.2 模型挂了时（路由链）

```
控制台每 8 秒增量扫 state/bridge.log
  └─ 出现失败信号（429 / quota / 积分耗尽 / upstream_connection_failed / 超时 …）
       └─ 该行提到当前生效条目（链首或链中段）？ → 切下一条（写 config.json + 桥接热生效 + DSH 默认）
            └─ 冷却 recoverMs 到点 → 自动切回链首
  保护：60 秒防抖、10 分钟内最多 5 次；切换历史见 state/chain-runtime.json
```

## 10. 2026-11 新增能力与配置

> 这些能力都在桥接侧；控制台设置页暂未提供图形开关，改 `config.json` 后重启桥接最稳妥。

### 10.1 活人感（`socialV2.presence`）

- 只补「这一轮怎么说话」：一两句为主、不列点、不总结、不复述、不客服腔；**0 额外模型调用**
- 只对 `chat` 回合生效；`vision` / `voice` / `web` / `sticker` 任务回合自动跳过
- 配置：`enabled`（默认 `true`）、`level`（`light` / `standard` / `off`）、`maxChars`（默认 `220`，硬上限）
- 关闭：`enabled: false` 或 `level: "off"`

### 10.2 回忆检索（`qq_search_history`）

- 归档：`state/message-archive/<group_群号|private_QQ>.jsonl`，每会话 5 万行后轮转 `.1`
- 检索会剥掉「你还记得 / 来着 / 了吧」等口语残留；短答案（`4只`）不按长度过滤；问「几只/多少」时额外扫「数字+量词」
- 命中带前后各一句；支持时间窗、发送者过滤；查询全是停用词时返回 `emptyQuery` 并提示换实词
- 工具面：`chat` 与 `web` 可见；closed-agent（管理员）也能用
- 范围：默认只查当前会话；`scope=user` + `userId` 时按 QQ 号跨群检索（**仅主人私聊 / closed-agent / 控制台管理端可用**，群会话会 403）
- 跨群索引：`state/user-index.jsonl`（单文件，默认 20 万行后轮转 `.1`；只记有 `userId` 的入站消息，不记自己发的）
- 配置：`socialV2.history = { enabled, maxLines, defaultHours, maxHits, userIndex, userIndexMaxLines }`
  - `enabled` 默认 `true`；`maxLines` 默认 `50000`；`defaultHours` 默认 `168`；`maxHits` 默认 `20`
  - `userIndex` 默认 `true`（关掉后 `scope=user` 只会查到已有索引）；`userIndexMaxLines` 默认 `200000`
- 关闭归档：`enabled: false`（已有归档文件不会自动删除）

### 10.3 跨群用户记忆（`socialV2.userMemory`）

- 以 QQ 号为主键，跨群/私聊共享一份关系：熟悉 / 信任 / 亲近 / 默契四维
- 半衰期 45 / 120 / 30 / 60 天；熟悉与默契用发言量饱和曲线（上限 92 / 90）
- 边界（称呼禁忌/偏好、敏感话题、玩笑、肉麻）**同一件事出现 2 次才确认**
- 每回合注入一行 `【对这个人】…`（只给档位词与已确认边界，不给分数、不给别人）
- 存储：`state/user-memory.json`（原子写，30 秒防抖）；只存数值与短句，不存消息原文
- 配置：`socialV2.userMemory = { enabled, maxUsers }`（默认 `true` / `5000`）
- 注意：只有 `reserved2` 模式的入站消息会更新关系；老用户从基线开始，未从历史回填

### 10.4 秘书旁路（`socialV2.secretary`）

- 默认关闭。开启后，非点名类群聊唤醒先问一次轻量模型「这轮要不要接」，拒绝就不叫主模型
- 点名类（@ / 名字 / 提问 / 拍一拍 / 私聊 / 管理员）**永远不经过秘书**；服务不可用/未配置/额度用尽一律放行
- 连续拒绝超过 `maxDeferMs` 会强制放行，避免小群被永久静默
- 配置：`socialV2.secretary = { enabled, baseUrl, apiKey, model, timeoutMs, maxCallsPerHour, maxDeferMs }`
  - 留空时回退 `config.api` 的 baseUrl/apiKey/model；默认 `maxCallsPerHour=120`、`maxDeferMs=900000`
- 观测：`state/secretary.jsonl`（每行含 allow/skip、模型、耗时）

### 10.5 风格画像（`socialV2.style`）

- 纯统计，学「怎么说」而不是内容：句长、短句比例、笑声密度、问句/感叹号、表情与语气词
- 门槛：样本 ≥ 120 且跨度 ≥ 72 小时才生成；变化小于 `minDistance` 不更新；只增不改，保留最近 3 版
- 群聊回合注入 `【本群说话习惯】…（样本 N 条）`；私聊不注入
- 存储：`state/style-profiles.json`（只存统计与摘要，不存原话）
- 配置：`socialV2.style = { enabled, inject, minSamples, minSpanHours, maxProfiles, freezeDays, maxVersions, minDistance }`
  - 默认 `true / true / 120 / 72 / 200 / 7 / 3 / 0.15`

### 10.6 出图（`imageGen` / `qq_generate_image`）

- **默认关闭**：`enabled: false`，未配置时工具返回可读原因，不会误发图
- 服务商：`openai`（含图生图 `/images/edits`）、`seedream`、`gemini`；`comfyui` 尚未接入
- 工具面：`web` 与管理员回合；参数 `prompt`、`size`、`referenceMessageId`（图生图只支持当前会话某条消息里的图）
- 落盘：`state/generated-images/YYYY-MM-DD/`；发送复用 OneBot 图片段
- 限额：`maxPerDay`（默认 20）、`minIntervalMs`（默认 5000）
- 配置示例：`imageGen = { enabled: true, provider: "openai", baseUrl: "https://api.openai.com/v1", apiKey: "…", model: "gpt-image-1", size: "1024x1024" }`

### 10.7 表情去重与入库审核（`socialV2.sticker`）

- `dhash = { enabled: true, threshold: 6 }`：收藏前用 ffmpeg 压成 9x8 灰度算 64 位指纹，与已入库表情比对；命中则不重复入库，并回滚预占的收藏额度
- 指纹由 `tools/ffmpeg/ffmpeg.exe`（或 `socialV2.voice.ffmpegPath`）计算；ffmpeg 不可用时**跳过去重但仍可收藏**
- 旧表情没有指纹：第一次重新收藏同一张时才会写入；纯色/无梯度图片的指纹全 0，无法区分
- 入库审核默认关闭：`review = { enabled: false, baseUrl, apiKey, model, failOpen }`
  - 开启后需填 `apiKey/model`（vision 模型）；缺配置、服务异常、返回无法解析，默认 **fail-closed 拒绝**
  - `failOpen: true` 可改为放行；审核规则是通用内容安全（色情/暴力/违法/不适/二维码广告/纯文字截图）

### 10.8 工具面变化（2026-11）

- `chat`：新增 `searchHistory`（回忆检索），其余工具面不变
- `web`：新增 `searchHistory`、`generateImage`
- 低频工具只从 schema 隐藏、执行期仍可用：`qq_send_group_message`、`qq_send_private_message`、`qq_memory_clear`、`qq_memory_remove`
- 成本观测：`npm run measure:schema` 会按功能域统计每回合下发的工具 schema 字节数

### 10.9 测试与运维

- `npm run test:presence` / `test:history` / `test:image` / `test:user-memory` / `test:sticker-dedup` / `test:secretary` / `test:style` / `test:dsh-delivery-retry`
